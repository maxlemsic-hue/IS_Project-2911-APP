# UI/UX Phase 3 — Admin product and catalog management

Implementation and disposable verification completed. Regular local activation awaits approval.

## Outcome and activation state

Implemented Owner/Admin product and category management, product attributes, safe image upload and management, catalog audit, and storefront image display. The full catalog workflow passed against a disposable PostgreSQL database. The regular local development database still has its original eight migrations. Approval was requested for only 20261120220000_catalog_management. No approval has been received as of this report.

The existing public product and ordering APIs retain their current data shapes and behavior. Storefront image retrieval uses a separate catalog endpoint with a placeholder fallback. Regular product management requires the new migration before it can be used.

## Features

- Responsive Angular Admin sidebar and /products page with search by product name or SKU, category filtering, product details, add/edit forms, exact decimal price entry, minimum quantities, selling units, draft/publication and availability flags.
- Category creation, editing, activity, sort order and archival.
- Optional named attributes, normalized keys and duplicate-key validation.
- Version checks prevent stale product saves. Product SKUs remain database-generated and immutable. Existing estimate/cost fields are preserved.
- Archival hides products or categories from new orders and preserves existing order snapshots. Archived records remain readable.
- Five active PNG/JPEG images per product, up to 5 MB and 8,192 pixels per side. Validation checks actual bytes. Server-generated UUIDs identify stored images, and client filenames are ignored.
- Image bytes are stored in PostgreSQL through the API, following the existing local receipt storage approach. Removal archives the image. Admin writes and private previews require Owner/Admin authorization. Public reads require current product/category visibility and send no-store, nosniff and restrictive CSP headers.
- The storefront displays the first active uploaded image and preserves the existing print placeholder when an image is absent or unavailable.
- Important catalog changes write to StaffAudit in the same transaction as the change. The UI displays actor, action and timestamp.

- Angular compilation initially lacked filesystem access in the sandbox. The permitted Windows rerun passed.
- The existing Admin tests needed provideRouter after adding navigation links. Updated their setup, retaining their assertions, then both passed.
- Test tooling needed a fresh isolated cluster because an earlier test cluster's temporary password file was absent. Fixed a password-file argument and temporary script escaping.

- Initial lint warnings from control-character validation were corrected, and the final check is clean.

## How to use after approved activation

Start PostgreSQL and run npm.cmd run dev. Sign in at http://localhost:4200/orders using Owner/Admin credentials, then open Products & categories or http://localhost:4200/products. Create a category if necessary, create a Draft product, save it, upload images with descriptions, then publish it and mark it available. Refresh http://localhost:3000 to see it. Customer cart, review, confirmation, manual payment and production rules remain in place.
