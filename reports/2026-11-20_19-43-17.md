# One-command development launcher

Started 2026-11-20_19-43-17 Asia/Manila (UTC+08:00).

## Work completed

Reviewed project instructions, README, vision, status and recent reports. Inspected root and workspace manifests, Nest API port configuration, Angular CLI ports, Next development flags and the API database check. Added npm run dev without changing npm dependencies or the four individual scripts.

The Node launcher checks IPv4 and IPv6 ports before starting any server. Windows listener enumeration detects overlaps that wildcard binds can miss. Occupied ports show the known PID and process name when accessible, then abort. The API-local PostgreSQL probe reads the existing runtime URL and issues SELECT 1. It accepts the configured loopback database, reports errors without credentials and performs no database writes or migration checks.

The launcher runs the existing scripts concurrently, prefixes output, keeps the API on port 3001 for this run and waits for four app-specific HTTP responses, including database health. It exits on child failure and attempts a normal shutdown of its own processes. Windows assigns waiting workers to a job before application startup, with kill-on-close cleanup for survivors and orphaned descendants. The alternate POSIX path uses owned process groups with a normal signal and a bounded forced fallback.

## Issues and resolution

The first Windows job manager launch lost its pipes in detached mode. Running the hidden manager attached with its own interrupt handler fixed the handshake. The initial wildcard-only port test missed Windows listeners on individual addresses. Combined the Windows listener snapshot with exact-address and wildcard probes and verified both collision families. An env-only startup fixture found that readFileSync did not support the attempted missing-file option. The final helper supports inherited variables with or without an API-local environment file.
