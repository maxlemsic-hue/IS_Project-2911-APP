# UI/UX Phase 2 — Multi-product cart and checkout

Implementation and verification in progress.

## Outcome

Implemented the real browser-persisted cart and dedicated /cart and /checkout routes in the existing Next.js app. Products come from the existing API. Product cards add their minimum quantities, repeated additions increase the quantity, cart fields allow quantity changes, items can be removed, and the header shows the total unit count. Cart and checkout calculate exact estimates with integer units of 0.0001 PHP. Customer details are collected at checkout.

Cart persistence contains only product IDs and quantities. Checkout failures retain the cart. Confirmed successful submission displays a single reference and private access code in the current page state, explains saving them, provides the tracking link and clears the cart. Codes are not stored in cart storage. The existing private lookup, confirmation, chat, notifications, receipt upload and progress tools remain available.

## Backend and database

POST /api/v1/orders accepts items with distinct product IDs and quantities. The legacy single-product payload is retained. Ambiguous mixed formats, empty or malformed arrays, duplicate IDs including case variants, and unsupported quantities are rejected. A maximum of 100 distinct lines bounds request work.

Every product is checked for publication, availability, archive and category eligibility. Each quantity is checked against its current minimum. Current server prices and product identity fields are snapshotted. One transaction creates the order and its nested items. Exact order total is included in the successful response. Existing Admin and customer screens already iterate all order items and use the shared total helper.

No Prisma model or migration changes were necessary. The single local database account remains in use. Test data was created using existing application endpoints and retained. Test-created staff accounts were deactivated after verification.

## How to run and demonstrate

Start PostgreSQL and run npm.cmd run dev from the root. Open http://localhost:3000, add two products, open Cart, change quantities and continue to http://localhost:3000/checkout. Enter demo contact details and submit. Save the returned reference and private access code. Use Track your order and enter those values. Owner/Admin reviews the same order at http://localhost:4200/orders. After availability, customer confirmation and manual verified payments, the existing production and release sequence continues.

## Remaining limitations and next task

Cart data is local to the browser. Refresh-based tracking remains in place. Prices are estimates until the API snapshots current catalog values at submission. Catalog images remain illustrative. Manual payment and stock review remain required. Catalog management for authorized owners is the recommended next task, including publication, pricing, minimum quantities, availability and actual product images.
