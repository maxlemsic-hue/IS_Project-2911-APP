## 5. Technical changes
Category has many Products; each Product belongs to one Category and has zero/many ProductAttributes. Unique lowercase canonical slugs, unique SKU, unique(productId,key), restrictive FK delete/update rules, Product.categoryId index. IDs use Prisma uuid(); updatedAt uses Prisma @updatedAt, so neither is promised as an SQL-level generated value for arbitrary direct SQL. ProductPublicationStatus DRAFT/PUBLISHED/ARCHIVED and ProductCostBasis REVERSE_CALCULATED_ESTIMATE/MANUAL_ESTIMATE. Both provenance labels are estimates, not acquisition cost. Optional text specifications preserved; no automatic parsing/variants/images. Default piece, minimum 1 (future importer must explicitly map source 25), DRAFT, unavailable and version 1.

Custom SQL adds 14 CHECKs: canonical slugs/nonempty required text, valid SKU format, finite nonnegative price/cost, positive minimum/version and provenance when cost supplied. Bigint NO CYCLE sequence assigns T29-P-000001-style identifiers with expanding width using lpad(...greatest(6,length(...))). BEFORE INSERT rejects supplied SKU then consumes exactly one nextval; BEFORE UPDATE rejects SKU change. dbgenerated() is no-expression trigger-assignment metadata, not an SQL default. No max+1, count-based or category/name-based logic. Sequence gaps from failed/rolled-back inserts are expected and never reclaimed; committed identity survives catalog edits/archival. Routine-role ownership/sequence privileges and restore high-water marks must be reviewed before application.

Important precision limitation: numeric(18,4) coerces input scale before row CHECKs; future write APIs/importers must reject excess precision before assignment. No silent-rounding financial code implemented; future posted PHP Decimal(18,2) explicit half-up rule documented only.
