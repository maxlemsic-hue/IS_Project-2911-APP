## Verification

- node apps/api/scripts/check-database.mjs passed the Prisma SELECT 1 connectivity check.
- node .tools/phase1a-live.mjs confirmed no public catalog tables, enums, functions or migration ledger. Both configured URLs use the same identity. It has database and public-schema ownership rights and CREATE privileges, with no superuser, create-role, create-database, replication or bypass-RLS flags.
- node .tools/phase1a-isolated.mjs passed. A non-superuser owner applied the original migration. Prisma migration status was up to date, repeat deploy found nothing pending, and schema diff was empty. Introspection still omitted the trigger-backed SKU default annotation.
- All three tables passed Prisma adapter checks. Passed 33 expected SQLSTATE rejections across unique identifiers, restrictive foreign keys, invalid values, immutable SKUs and permissions. All 24 parallel inserts received distinct SKUs. Rollback did not reuse the issued SKU, formatting expanded past six digits, and decimal precision, coercion and overflow behaved as expected.
- The isolated runtime role could write catalog rows with schema USAGE, table SELECT/INSERT/UPDATE and sequence USAGE. Sequence reseeding, trigger changes, schema creation and migration ledger reads were denied.
- npm.cmd run build and npm.cmd run test passed with approved filesystem access. All four apps built and Prisma Client generated. Ten unit tests passed.
- npm.cmd run lint, Prisma validate and the API test:e2e script passed individually. The API HTTP test uses a mocked database provider.

## Errors and limitations

The initial disposable harness launch overlapped the workspace build and could not import the compiled Prisma client while the output was being recreated. It passed after the API build finished. The combined lint/validate/e2e wrapper returned exit 1 despite successful-looking logs, so each command was rerun individually and returned 0. No migration defect was found. PostgreSQL rounds excess price precision before constraints run, so writes must validate decimal-string scale and range in the API. Backup and restore were outside this verification.
